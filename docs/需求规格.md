### 2.6 家当与余额（用户补充需求）

用户原话：*可以手动登记当前已有金额，名字为「登记当前家当」，不过这个界面放在不容易快速找到的位置吧，毕竟这是不常用的* ／ *还要有一个显示当前余额的界面，名字应该是「当前全部身家」，这样具有些许喜感* ／ *每一笔支出、收入记录应该要有对应的时间，手动登记的收支记录可以手动设置时间、类别*

| 编号 | 需求 | 优先级 |
|---|---|---|
| F-26 | **「当前全部身家」**：显示当前余额的独立界面，名字带喜感 | P0 |
| F-27 | **「登记当前家当」**：手动登记此刻真实拥有的总钱数 | P0 |
| F-28 | 登记入口**刻意放在不显眼处**（「当前全部身家」页右上角 ⋮ 菜单），因为不常用 | P0 |
| F-29 | 每笔收支记录都要显示时间（精确到分钟） | P0 |
| F-30 | 手动记账可**自选日期与时间**（用于补记过去的账） | P0 |
| F-31 | 手动记账可选择分类（支出与收入各自分类） | P0 |
| F-32 | 首页顶部显示「当前全部身家」入口 —— 余额是高频查看项，不该藏 | P0 |

**余额计算模型（不设账户期初余额）**：

```
当前全部身家 = 最近一次登记的家当 + 此后全部收入 - 此后全部支出
```

选这个模型的原因：传统记账 App 要求给每个账户设期初余额，一旦漏记就得一笔笔补。
而「登记家当」是**快照式对账** —— 漏记了只要重新登记一次，账立刻就对齐了。

| 编号 | 规则 | 说明 |
|---|---|---|
| F-33 | 从未登记过时，显示"记过的收入减支出"并**明确提示这不等于真实余额**，引导去登记 | 诚实优先，不用假数字骗用户 |
| F-34 | 每次登记产生一条快照记录，可查看历史、可删除 | 便于回溯"什么时候对过账" |
| F-35 | **对账差额自动识别与归类**（用户补充）：非首次登记家当时，若登记金额与账本余额**不一致** → 高则弹「**收入类型统计弹窗**」，低则弹「**消费类型统计弹窗**」；用户选定的类型作为**一笔正式流水入账**，标注为「家当对账」，差额不凭空消失 | P0 |

**F-35 的实现要点（有个容易算错的坑）**：

```
① 用户输入新家当 N，账本当前余额 B
② 差额 D = N - B
③ D > 0 → 弹收入类型窗（这笔钱是哪来的）
   D < 0 → 弹消费类型窗（这笔钱花哪了）
④ 用户选定分类后，写一笔流水：金额 |D|、方向按 D 的正负、分类为用户所选
⑤ 再写入快照 N
```

⚠️ **差额流水的记账时间必须早于快照时间**（实现里取 `recordedAt - 1`）。
因为余额 = 快照 + 快照之后（`occurredAt > recordedAt`）的净额；若两者时间相同或更晚，
这笔差额会被重复计入一次，余额直接算错。这一点已用本机 SQLite 做过 6 组场景推演验证。

### 3.2 触发优先级（已确认）

多个条件同时命中时（例：**17:30 在"鱼跃餐厅"消费 600 元**，同时满足 R-06/R-08/R-09），只展示优先级最高的一张。**已确认顺序**：

```
商户名彩蛋（R-09/R-10，稀有，惊喜感最强）
  ↓ 未命中
金额档（R-08 >500 → R-07 >100，冲击力最强）
  ↓ 未命中
分类 + 时间修饰（R-06 餐饮+17点后）
  ↓ 未命中
分类基础反馈（R-03/R-04/R-05，随机选一张变体）
  ↓ 未命中
兜底（R-11/R-12 无法分类 / 收入 R-13/R-14）
```

### 3.3 展示形式（已确认：方案 A · 悬浮窗全屏弹出）

**已选定：悬浮窗全屏弹出（TYPE_APPLICATION_OVERLAY）**

技术要点与硬性要求：
1. 必须申请 **「显示在其他应用上层」** 权限（`SYSTEM_ALERT_WINDOW`），需在权限引导页用图文引导用户开启——荣耀 MagicOS 会把它藏在「特殊应用权限」里。
2. Android 10 起禁止后台启动 Activity，**这是选悬浮窗而非 Activity 的根本原因**：悬浮窗走 WindowManager，不受该限制。
3. 弹出时机：识别成功 → 立即弹出 → 停留 ~2.5 秒 → 淡出；点击插画则进入该笔交易详情页。
4. 兜底策略：悬浮窗权限未授予或被系统拦截时，**降级为高优先级通知**（不能让反馈彻底消失）。
5. 悬浮窗内容：插画主体 + 台词 + 金额/分类/商户摘要 + 「撤销」按钮（误识别可直接在这里撤掉）。
6. 省电约束：同一笔交易只弹一次；连续多笔时不排队堆积，直接替换当前悬浮窗。

## 5. 从素材推断出的隐含需求（你没明说的部分）

1. **反馈是有"情绪分级"的** —— 小额平淡（线稿）、大额激烈（夺鲸霸拳）、彩蛋调皮。说明你希望记账这件事**有趣、有陪伴感**，而不是工具。
2. **「鲸元券」是收入的正反馈机制** —— 收入消息不只是"记上了"，而是用一种虚拟货币（Deepseek token 银行）来庆祝，带有强烈的自嘲玩梗色彩。
3. **17:00 后餐饮的特殊处理** —— 说明你考虑到了"晚饭"这个场景的情绪价值（先保护晚饭）。
4. **商户名含"鱼"的彩蛋** —— 说明你希望 App 能在日常中给到**意外的小惊喜**，这是留存的关键。
5. **"无法确定消费类型"专门做了两张图** —— 说明你预期**分类失败是常态**，需要好好处理这个状态，而不是简单丢个"其他"。
6. **手动登记收入专门做了动图** —— 说明**手动补录在你的使用场景里占重要位置**（自动识别一定有漏，需要顺畅的补录体验）。
7. **"免死鲸牌"** —— 记账 App 的痛点心理是"花了钱有负罪感"，这个名字暗示了一种**"花了就花了，我赦免你"**的轻松态度。
